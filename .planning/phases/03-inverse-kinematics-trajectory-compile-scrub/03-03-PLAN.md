<objective>
Make the scrub-to-pose correspondence visible. A marker rides the toolpath at the current scrub position,
and the control itself reports where it is and states plainly when there is nothing to scrub.

Purpose: this phase's entire job is proving IK correctness before any animation exists, and a reviewer
can only judge that if they can see, simultaneously, where the control says the tool is and where the arm
has actually put it. A slider that moves a robot with no on-path reference point is not a proof.
Output: D-07's indicator, a readable scrub control, and the phase's visual sign-off.
</objective>

**Step 1 — `src/scene/ScrubMarker.tsx`.** A component holding a `mesh` ref and driving it imperatively.

Read nothing reactively. Inside `useFrame`, call `useCellStore.getState()`, take `trajectory` and
`scrubFraction`, and bail out when the mesh ref is unset, the trajectory is null, or its sample array is
empty. Map the fraction onto a sample index using exactly the same rounding the pose driver in
`RobotPose.tsx` uses — this is the load-bearing detail: both must resolve the same index from the same
fraction, so the marker and the arm are always reporting the same sample. If the two disagree, the marker
would imply a positional accuracy the arm is not actually achieving. Set the mesh's position from that
sample's `point`, lifted by the marker's own radius on the vertical axis, reusing the reasoning
`Toolpath.tsx` documents for its own markers: a sphere centred on a point that sits exactly on the
workbench surface would be clipped in half by that opaque surface.

Toggle the mesh's visibility with the same guard, so no marker is rendered before a sample is compiled.

Render a single sphere mesh — one indicator, not a pair, and explicitly not a per-operation marker, which
is Phase 6's job. Define two module-level constants with comments: a radius meaningfully larger than
`Toolpath.tsx`'s start/end markers so the current-position indicator reads as the primary one, and a new
colour constant. Choose a tone that is clearly distinguishable from both the muted gray rapids and the
warm orange cutting line and start/end markers, reads against the Dominant background and the Secondary
floor and workbench, and stays clear of the reserved Accent blue — a deep teal is a good fit. Record in
the comment which tones it must not collide with and why, matching the discipline `Toolpath.tsx`'s own
colour header already establishes.

**Step 2 — `src/scene/CellScene.tsx`.** Mount `ScrubMarker` inside the Canvas immediately after
`Toolpath` and before `OrbitControls`, and extend the composition-order comment block to name it, in the
same style the existing entries use. The marker's position arrives already in world space, so it takes no
wrapping group or transform, exactly like `Toolpath`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| compiled trajectory → scene geometry | A sample's stored point crosses into a rendered mesh position, where a non-finite value would remove the marker from the scene without any error |
| DOM control → store | The range input's value crosses into `setScrubFraction`, the only write path this control has |
