    - The same start/end/centre traversed clockwise returns a polyline sweeping the complementary 270 degrees, i.e. it contains at least one point whose XY position is farther from the straight chord than any point of the counter-clockwise result.
    - A full circle (start equals end, non-zero radius) returns a closed polyline sweeping a full turn rather than returning a single degenerate point.
    - A degenerate arc whose start, end and centre all coincide returns exactly the two endpoints and no intermediate points.
    - The point count scales with the swept angle: a quarter turn yields roughly a quarter of `ARC_SEGMENTS_PER_TURN` intermediate points, plus the two exact endpoints.
    - Every returned coordinate is finite for every case above.
  </behavior>
  <action>
Write the test file first, encoding the cases in the behaviour block above, and confirm it fails before
writing the implementation.

Export `const ARC_SEGMENTS_PER_TURN` (a fixed angular resolution — a value in the 48–96 range keeps a
150 mm-scale arc smooth without inflating the vertex count) and
`function tessellateArc(center: readonly [number, number, number], start: readonly [number, number,
number], end: readonly [number, number, number], direction: 'G2' | 'G3'): [number, number, number][]`.

All three inputs are in the interpreter's own coordinate convention, where the arc always lies in the
XY plane and Z interpolates linearly from start to end (helical moves). Compute the start and end
angles with `Math.atan2` relative to the centre and the radius from the centre-to-start distance. `G2`
is clockwise (decreasing angle) and `G3` is counter-clockwise (increasing angle); take that direction
from the caller, never from a boolean, because the interpreter does not pass one. Normalise the swept
angle into the open interval `(0, 2π]` in the traversal direction, so a start angle equal to the end
angle sweeps a full turn instead of collapsing to nothing. Emit the exact `start` tuple, then the
intermediate points at a uniform angular step derived from `ARC_SEGMENTS_PER_TURN`, then the exact `end`
tuple — the endpoints must be the caller's own values copied verbatim, not recomputed from the angle,
so an arc's last point is bit-identical to the next segment's first point and no seam appears at the
junction. Return the two endpoints alone when the radius is zero. Do not clamp, round or otherwise
alter finite input values.

Do not handle the ZX or YZ working planes here. The interpreter remaps the x/y/z fields of its arc
arguments per the active plane before calling back, and both bundled samples are authored on the
default XY plane only (D-08, and enforced by Task 2's acceptance criteria), so a remap-aware branch here
would be untested code guarding a case the bundled assets cannot produce. Record that constraint in the
module's header comment so a future upload feature knows what it must add.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bundled `.gcode` asset → parser | Developer-authored text becomes WebGL geometry; the same entry point a future upload feature would reuse |
| parser output → bounding box / camera math | A non-finite value here silently corrupts every downstream geometric computation |
