  <action>
Create `src/scene/ToolpathCameraFit.tsx` as a default-exported in-Canvas component that renders null,
structurally mirroring `CameraResetListener.tsx`. Read `camera` and `controls` from `useThree`, and read
`selectedSampleId` and the parsed `toolpath` from the cell store. Run one `useEffect` keyed on
`selectedSampleId` alone, with the same deliberate narrow-dependency eslint suppression and a comment
explaining why the dependency array is narrow, exactly as the reset listener does.

Unlike `CameraResetListener`, this component must **not** skip its first run. The reset listener skips
the initial mount because the camera already sits at the default framing and moving it unprompted would
be a camera move the user did not ask for; here the first sample selection is precisely when the fit
should first apply, and no sample is loaded at all until the user picks one — so there is no unwanted
initial move to guard against.

Effect body: return early when controls are absent or the toolpath has null bounds. Otherwise take the
`bounds` the parser already computed (world-space, anchor applied) rather than recomputing a bounding
box by traversing the scene graph — the numbers already exist and traversal would be strictly more work
for the same answer. Derive the box centre and size from `bounds`, take the largest of the three
dimensions, and compute the camera distance from that dimension and the perspective camera's vertical
field of view in radians, multiplied by a padding factor a little above 1 so the path does not touch the
viewport edges. Preserve the current viewing *direction*: take the normalised vector from the controls
target to the camera position, and place the camera at the box centre plus that direction scaled by the
computed distance, then set the controls target to the box centre and call the controls update. Framing
the new bounds from the angle the user is already looking from avoids an unexplained rotation on every
selection.

Guard the arithmetic: if the largest dimension is zero or non-finite, leave the camera untouched rather
than producing a non-finite camera position, which would blank the canvas with no error.

Mount `<ToolpathCameraFit />` inside `CellScene.tsx`'s Canvas as a sibling of `<CameraResetListener />`,
after it, keeping the documented composition order intact. Do not modify `CameraResetListener` or
`camera-defaults.ts`: D-05 adds a new framing behaviour and explicitly does not replace the Phase 1
default that Reset View restores.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caught parser/fetch exception → DOM | An exception message rendered verbatim can leak internal paths or library internals into the page |
| parser bounds → camera transform | A non-finite or zero-size bound propagates into the camera position and blanks the canvas silently |
| concurrent user selections → single store slot | Two in-flight loads racing for one piece of state |
