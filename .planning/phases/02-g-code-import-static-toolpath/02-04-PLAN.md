<objective>
Close two related UAT gaps from the same root cause area — the toolpath's world-space placement. The
developer's live sign-off on Phase 2 (02-UAT.md, Test 1) reported the print sample sitting too low with
no surface to rest on (G-02-01) and overlapping the rail rig's carriage instead of clearing it (G-02-02).
Both trace to `src/gcode/toolpath-anchor.ts`'s D-06 anchor: Y was hardcoded to the bare floor plane, and Z
was derived as a flat fraction of `ROBOT_REACH_ENVELOPE` with no relationship to the carriage's actual
footprint.

**Why this is safe to change now (not a locked decision).** 02-01-PLAN.md rated D-06 "costly to reverse"
*only* because Phase 3's IK targets would depend on it once Phase 3 executes. Phase 3 has not been
planned or executed (ROADMAP.md: "Plans: TBD") — there are zero downstream consumers of the previous
anchor values. The developer's own UAT feedback supersedes the prior rating; this plan changes the anchor
derivation directly, not through a `checkpoint:decision`.

Purpose: the toolpath's rendered position is the single most visible artifact of this phase — floating
over a bare floor or overlapping the rig reads as broken even though the parser and classification are
correct underneath it.
Output: a workbench the toolpath visibly rests on, positioned with a real clearance gap in front of the
carriage, still verifiably inside the robot's reach envelope.
</objective>
