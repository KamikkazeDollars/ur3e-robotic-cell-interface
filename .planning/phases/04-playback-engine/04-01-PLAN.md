<objective>
**As a** person evaluating this robotic cell interface, **I want to** press a Play
button and watch the UR3e run the whole imported toolpath by itself, **so that** I
can see the cell actually working instead of having to drag a slider by hand.

This is the phase's tracer slice: it wires a real DOM Play/Pause control through a
real animation clock, through the store, into the already-existing pose and marker
drivers — one path, end to end, production quality. Everything Phase 4 adds after
this (weighted rapid/cut timing, interpolated sample lookup) expands outward from
this proven path without changing its shape.

Purpose: prove the dual-cadence architecture end-to-end before building on it. The
load-bearing risk this slice retires is that `scrubFraction` is a *reactive*
Zustand field read by `ScrubControl.tsx`; writing it 60 times a second would
re-render that control every frame — the exact anti-pattern CLAUDE.md, the store's
own file header, and PITFALLS.md Pitfall 10 all forbid. The slice proves the split
(non-reactive `livePlayback.fraction` at 60fps, throttled reactive `scrubFraction`)
actually drives a smooth robot and a live slider at the same time.

Output: a working Play/Pause control, a pure clock core with unit tests covering
D-01/D-05/D-06/D-07, a headless end-to-end playback run test, and D-04 pause-on-drag.
</objective>

**Layer 1 — `src/playback/clock-step.ts` (new, pure, framework-free).** Follow
`src/trajectory/arc-length.ts`'s module discipline exactly: no React import, no
Three.js import, no store import, and a header comment stating that constraint.
Export these constants: `PLAYBACK_TOTAL_DURATION_SECONDS = 10` (D-01, with a
comment naming D-01 and stating the value is deliberately normalized rather than
derived from g-code feed rates), `MAX_FRAME_DELTA_S = 0.1`, `RESUME_EPSILON = 1e-3`,
`STORE_SYNC_INTERVAL_S = 0.08`. Export an interface `FractionMapping` with two
methods, `elapsedToFraction(elapsedSeconds: number): number` and
`fractionToElapsed(scrubFraction: number): number` — this is the seam plan 04-02
replaces with the D-02 weighted mapping without changing any signature. Export
`UNIFORM_FRACTION_MAPPING: FractionMapping` implementing the arc-length-uniform
case (`elapsedSeconds / PLAYBACK_TOTAL_DURATION_SECONDS` and its inverse, both
clamped into [0, 1] and [0, PLAYBACK_TOTAL_DURATION_SECONDS] respectively). Export
`resumeElapsedSeconds(scrubFraction, mapping)`: return 0 when `scrubFraction` is
non-finite or is greater than or equal to `1 - RESUME_EPSILON` (D-07 — document
inline that this is the one case where Play does not resume from the literal
current fraction, because D-05 and D-06 together leave a completed run ambiguous
and a literal resume from 1 would be a zero-duration play that looks like nothing
happened); otherwise return `mapping.fractionToElapsed(scrubFraction)` clamped into
[0, PLAYBACK_TOTAL_DURATION_SECONDS] (D-05). Export interfaces
`ClockState { elapsedSeconds: number; sinceSyncSeconds: number }` and
`ClockStep { elapsedSeconds: number; sinceSyncSeconds: number; fraction: number; finished: boolean; shouldSync: boolean }`,
and `stepClock(state, rawDeltaSeconds, mapping): ClockStep`, which: coerces a
non-finite or negative `rawDeltaSeconds` to 0 and caps it at `MAX_FRAME_DELTA_S`
(document that a backgrounded tab's resumed frame can carry a multi-second delta
and would otherwise jump or end playback in one frame); adds the capped delta to
both accumulators; sets `finished` when elapsed reaches
`PLAYBACK_TOTAL_DURATION_SECONDS`; sets `fraction` to exactly 1 when finished and
otherwise to `mapping.elapsedToFraction(elapsed)` passed through the same
finite-then-clamp guard the store's `setScrubFraction` uses, so a degenerate
mapping can never emit NaN or Infinity; sets `shouldSync` when finished or when
`sinceSyncSeconds` reaches `STORE_SYNC_INTERVAL_S`, and returns
`sinceSyncSeconds: 0` in that case.

**Layer 2 — `src/store/cellStore.ts` (extend, do not restructure).** Change the
creator to `create<CellState>((set, get) => ({ ... }))`. Add to `CellState`, each
with a doc comment: `isPlaying: boolean` plus `play: () => void` and
`pause: () => void`, mirroring the `robotLoadStatus`/`setRobotLoadStatus` reactive
discrete-toggle convention (a Play press is human-interaction cadence, so a normal
reactive field is correct); and `livePlayback: { fraction: number }`, a

whose `.fraction` is assigned directly (never through `set()`) so Zustand notifies
nobody. Document on `livePlayback` that this is the non-reactive 60fps channel the
scene's per-frame consumers read, and that it exists because `scrubFraction` is
reactive and already has a subscribed DOM consumer. Extend `setScrubFraction` to
compute the clamped value once (reuse the existing
`Number.isFinite(fraction) ? Math.min(1, Math.max(0, fraction)) : 0` expression,
do not introduce a second looser clamp), assign it to `get().livePlayback.fraction`,

every manual drag and on every throttled clock sync, and the scene never reads a
stale value between syncs. `setScrubFraction` must NOT touch `isPlaying`: the
playback clock routes its own throttled writes through this same setter, so

**Layer 3 — `src/playback/usePlaybackClock.ts` (new).** Mirror
`ScrubMarker.tsx`'s import shape and its `useFrame` + `useCellStore.getState()`
idiom. Hold three refs: the `ClockState`, the active `FractionMapping` together
with the `ParsedToolpath` object identity it was built for, and a
`wasPlayingRef` boolean. Inside `useFrame((_state, rawDelta) => ...)`: read
`isPlaying`, `toolpath`, `trajectory`, `scrubFraction`, `setScrubFraction`,
`pause`, and `livePlayback` from `useCellStore.getState()`; if `isPlaying` is
false, or there is no trajectory, or `trajectory.samples.length` is 0, set
`wasPlayingRef` to false and return. Rebuild the mapping ref whenever it is null
or its recorded toolpath identity differs from the current `toolpath` — in this
plan that means assigning `UNIFORM_FRACTION_MAPPING` (plan 04-02 swaps in
`buildDurationMapping(toolpath, trajectory)` here with no other change). Then, on
the transition into playing (`wasPlayingRef` false), set `wasPlayingRef` true and
reset the clock state to
`{ elapsedSeconds: resumeElapsedSeconds(scrubFraction, mapping), sinceSyncSeconds: 0 }`.
Re-seeding on the transition rather than only on a toolpath change is load-bearing
and corrects the sketch in 04-RESEARCH.md: a user who pauses, drags the slider,
and presses Play again must resume from the dragged position (D-05), which only
happens if the elapsed seed is recomputed on every Play press. Call `stepClock`,
store the returned accumulators back into the ref, assign `step.fraction` to
`livePlayback.fraction` on every frame, call `setScrubFraction(step.fraction)`
only when `step.shouldSync`, and when `step.finished` call `pause()` and set
`wasPlayingRef` to false (D-06: the run stops, the final pose is held because
`livePlayback.fraction` stays at 1, and the control reads "Play" again). This hook
must never solve inverse kinematics and must never import from `src/kinematics` —
Phase 3 already precomputed every pose, and re-deriving one here would reintroduce
the branch-flip and singularity failures Phase 3 closed.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser rAF scheduler → playback clock | `useFrame`'s `delta` is supplied by the browser and is not guaranteed small, positive, or finite — a backgrounded or throttled tab can deliver a multi-second delta on the frame after refocus. |
| store write path → 3D scene | Every fraction written into `livePlayback.fraction` or `scrubFraction` is consumed by `setJointValue` and `mesh.position.set`; a non-finite value there corrupts the scene graph rather than throwing. |
